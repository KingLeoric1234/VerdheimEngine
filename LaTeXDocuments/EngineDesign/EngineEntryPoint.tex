\section{Engine entry point: The life cycle of the game.}

\subsection{Entry Point. File: EntryPoint.c}
\begin{enumerate}[label = Step\arabic*]
	\item	Program execution: Player click the game and execute it.
	\item	Allocate memories for every units: Sprites, Renderer.
	\item	Register Windows.
	\item 	Initialize rendering program.
	\item 	\textbf{Begin the windows loop.} (The core of gaming loops. More details, see \ref{FrameLoop}).
	\item	rendering shutdown.
	\item	free\_memories.
\end{enumerate}

\subsection{Frame Loop. File: HWND.c}
\begin{enumerate}[label = Step\arabic*]\label{FrameLoop}
	\item 	Program state checking: If program running state is true, then begin the frame loop.
	\item	Peek Message (Windows API): Detect whether player pressed the Key code, this API will help us to detect the key code instantly.
	\item	\textbf{Update rendering:} when peek message finished, then execute the rendering update. Draw the current prepared frame. More details, see \ref{Update}.
	\item   Time counter: We use frame to define the game's minimum time. The time counter defined in the Timer.c file.
	\item   Back to the Step 1. Check whether the program running, if running, then prepare for the next Peek Message and new frame drawing. If not, then shut down the frame.
\end{enumerate}
